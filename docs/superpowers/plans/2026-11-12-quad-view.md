# Quad View Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A `quad.html` page that shows four WeatherStar shows in a 2 by 2 grid, with NWS warning alerts that can be acknowledged, plus a RainViewer radar screen for Hawaii, deployed to GitHub Pages.

**Architecture:** `quad.html` is a wrapper of four same-origin iframes, each loading the unchanged app (`index.html`) with a permalink and a `quad=1` flag. A tiny classic script in the app swaps `localStorage` for an in-memory store when `quad=1` is present, so the four boxes never share settings. The wrapper polls NWS alerts itself, classifies them with pure tested functions, and drives borders, tags, takeovers and acknowledgments. Hawaii radar is a new display module that only runs for HI and AK.

**Tech Stack:** Plain ES modules in the browser (no bundling for quad code), `node --test` for unit tests (Node 20+, no new dependencies), the existing gulp build, GitHub Actions for Pages.

**Spec:** `docs/superpowers/specs/2026-11-12-quad-view-design.md`

## Global Constraints

- Towns, in box order 1 to 4: Bolivia, NC (34.0671, -78.1481); Durango, CO (37.2753, -107.8801); Sunriver, OR (43.8840, -121.4386); Poipu, HI (21.8817, -159.4600). Town-center coordinates only. **Jen's house location must never appear in the repo, the build, or the deployed site.**
- Alert source: `https://api.weather.gov/alerts/active?point=<lat>,<lon>&status=actual`.
- Level 2 events: `Tornado Warning`, `Hurricane Warning`, `Flash Flood Warning`, or any alert with `severity === 'Extreme'`.
- Tag-only (frequent) events: `High Surf Warning`, `Red Flag Warning`, `Excessive Heat Warning`, `Heat Warning`, `Extreme Heat Warning`. One exported list.
- Timings: takeover 30 s, cycle 5 min, alert poll 3 min. Exported constants.
- Music from box 1 only. Boxes 2 to 4 get `mediaPlaying=false`.
- No sound alerts. No other APIs. No change to how a single show looks. Mainland radar untouched.
- Keep upstream edits minimal: new code goes in `server/scripts/quad/`, `server/quad.html`, `server/styles/quad.css`, and `server/scripts/modules/hawaii-radar*`. Edits to upstream files are limited to: `views/index.ejs` (one script tag, one display div), `server/scripts/ws.mjs` (one import), `gulp/build.mjs` (`otherFiles` entries), `package.json` (one script), new workflow file.
- All new code passes `npm run lint`.
- Paths in HTML stay relative (no leading `/`), because Pages serves the site from `/ws4kp/`.

## Review Focus

1. **NWS fetch fails or the Mac is offline** for a town: that box keeps its last known alert state and the page does not throw. Test in Task 4 (`keeps last state when fetch fails`).
2. **A warning expires:** on the next poll the border and tags clear, and its acknowledgment is pruned. Test in Task 1 (`prunes acks for alerts no longer active`).
3. **Two towns at Level 2 at once:** takeovers take turns and never overlap. Test in Task 4 (`two level 2 boxes take turns`).
4. **New, unrelated warning in a town whose earlier warning was acknowledged:** the new one alerts at its own level even if lower. Test in Task 1 (`new unrelated alert is not acknowledged`).
5. **Cancel messages** (`messageType === 'Cancel'`) must not light anything up. Test in Task 1 (`cancel message is ignored`).

### Task 1: Alert classification and acknowledgment logic

**Files:**
- Create: `server/scripts/quad/alert-levels.mjs`

- Test: `tests/quad/alert-levels.test.mjs`, `tests/quad/ack-store.test.mjs`

**Interfaces:**
- Produces, `alert-levels.mjs`:
  - `LEVEL = { NONE: 0, TAG: 1, WARNING: 2, EXTREME: 3 }`
  - `LEVEL2_EVENTS: string[]`, `TAG_ONLY_EVENTS: string[]` (values from Global Constraints)
  - `classifyAlert(properties) -> number` where `properties` is an NWS alert feature's `properties` object.
  - `townStatus(features, acks) -> { level, acknowledged, label, tags }` where `level` is the highest LEVEL among unacknowledged alerts (or the highest acknowledged one if all are acknowledged), `acknowledged` is true when every alert at WARNING or above is acknowledged, `label` is the highest-level event name in caps, `tags` is an array of event names at TAG level.
- Produces, `ack-store.mjs`:
  - `isAcknowledged(properties, acks) -> boolean`
  - `acknowledgeAll(features, acks) -> acks` (returns a new object)
  - `reconcile(features, acks) -> acks` (inherit through `references`, then prune)
  - `loadAcks(storage) -> acks`, `saveAcks(storage, acks)`; storage key `quadAcks`.
  - `acks` shape: `{ [alertId: string]: level: number }`, `alertId` is `properties.id`.

  - `any Extreme severity is extreme`: `{event:'Blizzard Warning', severity:'Extreme'}` → `EXTREME`
